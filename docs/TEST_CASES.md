# Q Note 完整测试用例与迁移验收

本文将 [功能规格](./FEATURES.md) 展开为可以直接编写测试代码的场景。适用于 main 的回归，以及更换框架、语言或桌面容器后的等价验收。用例不绑定组件名、模块路径或测试工具。历史迁移计划、当前实现和截图不能覆盖功能规格中的明确要求。

**本文是测试要求，不是已执行报告。新增或阅读本文不会使任何用例自动通过。** 每条用例默认“未执行”；已有实现的已知差异见第 23 节。未来 AI 必须生成测试并记录实际结果。

## 1. 阅读与编写测试的规则

1. 完整阅读 [AGENTS.md](../AGENTS.md)、[FEATURES.md](./FEATURES.md)、本文及 [Windows 已修复问题与回归约束](./WINDOWS_REGRESSIONS.md)，再查看 [主面板参考图](./images/q-note-main.png)、[编辑窗口参考图](./images/q-note-editor.png)。README 只用于入口和当前技术栈命令。
2. 根据编号建立“用例 → 测试文件/测试名称 → 平台/参数 → 结果/证据”的映射。编号不得因技术栈变化重排或复用；新增用例顺延，删除要求需注明原因。
3. 一条用例的多个参数必须分别执行，报告不得用一个参数通过代替整行。正文中的“分别”“逐一”“每个入口”均表示独立变体。
4. 每条用例由前置、步骤、预期组成；第 2–4 节的通用断言、数据和环境同时生效。异步操作以可观察完成条件结束，不用固定睡眠掩盖竞争问题。
5. 有“重启”时必须结束测试实例并用同一隔离数据重新启动，不能仅重新挂载界面；有“落盘”时必须重新打开存储检查。取消、失败和未授权的安装不能当作成功流程执行。
6. 模拟接口适合故障注入及状态测试；标题栏、窗口位置、真实拖动、托盘、系统开机启动和 DPI 必须有真实桌面验证。网页预览通过不能代替原生验收。
7. 测试的期望值来自规格和固定数据，不能从被测函数返回值或当前截图动态生成。发现旧实现不满足要求，记录失败和差异，不修改断言去迁就缺陷。
8. 只创建完成验证所需的测试代码；临时脚本、临时数据、故障注入和测试进程完成后清理。复杂行为的长期回归可以保留。不得使用或覆盖用户真实数据库。

## 2. 环境、精度、优先级与共同断言

### 2.1 执行层级

| 标记 | 执行层    | 能证明什么                                                      |
| ---- | --------- | --------------------------------------------------------------- |
| L    | 数据/规则 | 排序、格式兼容、归一化、边界运算；不能证明 UI 或系统效果        |
| I    | 隔离集成  | 真正的数据库事务、存储重开、文件往返、跨窗口通信；外部服务可控  |
| U    | 可见 UI   | 内容、几何、焦点、键盘、鼠标、遮罩、动画及操作冲突              |
| N    | 原生桌面  | 操作系统窗口、托盘、工作区、DPI、多显示器、原生文件框、真实指针 |

优先级：P0 为数据丢失、无法启动、无法保存/恢复及关键迁移兼容；P1 为完整功能和高频交互；P2 为视觉细节、动画及扩展组合。优先级不表示 P2 可以省略。

### 2.2 必跑环境矩阵

| 维度   | 参数与覆盖要求                                                                    |
| ------ | --------------------------------------------------------------------------------- |
| 语言   | zh、en；默认语言另测 zh-CN、ZH-TW、en-US、fr-FR                                   |
| 系统   | Windows、macOS、Linux；仅针对某系统的能力在其他平台标明理由，不伪报通过           |
| 窗口   | 主窗 300×450、600×650、1000×800；编辑窗 420×520、520×640、1000×800                |
| DPI    | 100%、125%、150%、200%；组件设计尺寸与物理截图测量分别记录                        |
| 显示器 | 单屏；副屏在左侧/上方形成负坐标；同 DPI 双屏；混合 DPI 双屏；运行中拔掉副屏       |
| 工作区 | 底部/左侧/顶部任务栏或 Dock；可用工作区不足最大窗口；贴边相邻屏幕                 |
| 数据   | 空库、标准数据、多附件、长文本、旧结构、无效设置 JSON、无效恢复 JSON、只读/故障库 |
| 网络   | 正常、404、断开、慢速、长度未知、传输中断、校验错误；图片与更新分别验证           |

不是所有用例都做全笛卡尔积：存储用例至少跑三系统存储实现；每项可见交互至少跑中英文；所有几何、拖动和窗口用例必须跑 DPI 与屏幕矩阵。跨特性专项组合见第 20 节。

### 2.3 测量与等待规则

- 精确布局在设计坐标中断言，误差不超过 1 个设计像素；物理坐标先按该系统和显示器缩放换算，再允许 1 个物理像素的取整误差。不能把容器 CSS 尺寸代替实际外框尺寸。
- 文本换行使用实际渲染行数；测试固定字体、字体大小、宽度和系统，禁止按字符数猜测行数。跨系统字体栅格化差异可使用分别维护的图片基线，尺寸、结构、颜色仍须满足规格。
- “约”时长是目标而非每帧硬实时保证。可控时钟验证定时器在边界前不触发、边界到达触发；桌面录制验证方向、终点、无振荡，注明刷新率和调度误差。不得随意放宽为数秒。
- 1.7 秒提示：可控时钟 1699ms 可见、1700ms 开始结束；淡出完成后不能继续拦截输入。窗口保存约 300ms 用连续事件合并及最后状态落盘断言，不能规定每个移动事件都写库。
- 超时只作为测试停止条件，不能当作产品行为本身。5000ms 编辑准备超时、300000ms 位置缓存等精确定时按各用例边界执行。

### 2.4 每条用例共同断言

- 没有未处理异常、无限加载、重复窗口、不可恢复遮罩或失效操作区域。
- 非目标便签的 id、正文、附件、时间、颜色、排序和设置保持不变；单项修改不得暗中改写其他字段。
- 不应写入的操作：hover、查看预览、复制、关闭菜单、取消文件框、取消编辑不得提交便签修改。
- 成功提示只在成功后显示一次；失败显示对应动作的错误，不显示成功；静默更新和无操作取消按各自规则保持安静。
- 对写入失败，用失败前快照、失败后 UI、失败后重开数据库和重启结果四处比较；不能只检查调用了回滚函数。
- 每次操作只触发一次相应动作；按钮、菜单、遮罩、图片、调整高度或拖动不得连带复制/删除/恢复主窗。
- 涉及便签写入成功后，读取数据库、重启、导出至少采用一种独立观察核对；标明要求重启的用例必须重启。

## 3. 固定测试数据

### 3.1 时间、标识和设置

冻结时钟 `T0 = 1800000000000`，每次显式保存推进 1000ms；导出文件名和每日 17:00 测试另设本地日期，并记录时区。生成的新标识必须非空且彼此不同，不要求具体随机算法。

默认设置 S0：language 按系统；alwaysOnTop=false、autoStart=false、dockOnEdge=false、docked=false、dockEdge=null、keepFullMain=false、window=null。标准设置 S1：language=zh、alwaysOnTop=true、autoStart=false、dockOnEdge=true、docked=false、dockEdge=right、keepFullMain=false，window={width:600,height:650,x:500,y:120}。系统真实开机启动状态可独立置为 true/false，不能由设置夹具冒充系统状态。

### 3.2 便签集合 N1

每条创建时间为 T0-10000、附件为空、textHeight=null；未列出的颜色取默认色。按以下表生成，输入数组顺序故意打乱为 C、A、E、B、D。

| id  | content           | pinned | sortOrder | updatedAt | 初始显示序号 |
| --- | ----------------- | ------ | --------- | --------- | ------------ |
| A   | 置顶甲 / Pinned A | true   | 0         | T0-3000   | 1            |
| B   | 置顶乙 / Pinned B | true   | 1         | T0-1000   | 2            |
| C   | 普通甲 / Normal C | false  | 0         | T0-4000   | 4            |
| D   | 普通乙 / Normal D | false  | 0         | T0-2000   | 3            |
| E   | 普通丙 / Normal E | false  | 2         | T0-5000   | 5            |

基准顺序固定为 **A、B、D、C、E**。每条用例从独立副本开始，不能继承上一用例的置顶或排序变化。

### 3.3 文本与附件夹具

| 标识      | 值/构造                                                              | 使用目的                          |
| --------- | -------------------------------------------------------------------- | --------------------------------- |
| TXT-ONE   | `hello world!`，在当前宽度实际为 1 行                                | 单行 41px                         |
| TXT-FIVE  | `first\nsecond\nthird\nfourth\nfifth`，这里的 \n 是真实换行          | 默认 2 行，完整 5 行              |
| TXT-WRAP  | 固定宽度下实测为 2 行，增宽后为 1 行的中英文文本；保存精确文本和宽度 | 宽度重算，不以 34 字符作替代      |
| TXT-TRIM  | `  first  line\n\n second line  `                                    | 首尾 trim、内部两个空格和空行保留 |
| TXT-WHITE | 空串、空格、制表符、换行的各独立变体                                 | 空便签、附件复制                  |

### 3.5 故障夹具

每项故障能单独开关并在一次失败后恢复：读取数据库失败、读取设置失败、设置非法 JSON、写便签失败、删除附件后写正文失败、替换数据写到第二条失败、顺序写到第二条失败、提交失败、导出文件不可写、文件对话框取消、系统置顶失败、系统开机启动失败、剪贴板不可用、图片 404/坏字节、更新检查失败/慢响应/传输停滞/错误大小或 hash/安装准备失败/安装失败。事务内“中途失败”需要真实数据库或可验证事务隔离，不能用一开始拒绝调用代替。

## 4. 启动、主窗口与标题栏

依据：FEATURES §2、§3、§14；关键断言以真实窗口状态和重开数据为准。

### BOOT-001 首次启动 [P0 I/U/N]

- 前置：隔离主目录，无新旧数据库；系统语言分别 zh-CN、ZH-TW、en-US、fr-FR。
- 步骤：普通启动，等待加载结束；关闭主窗后托盘恢复，再正常退出并启动。
- 预期：完整主面板出现、空列表和新建入口可用、计数 0；默认语言依次 zh、zh、en、en；采用 S0；数据库可读，恢复/重启不产生便签。

### BOOT-002 已有数据启动 [P0 I/U/N]

- 前置：N1+S1 数据库，另把会话字段改为 docked=true、keepFullMain=true、dockEdge=right。
- 步骤：启动；读取持久设置；再次退出重启。
- 预期：两次均显示完整主窗，顺序 A/B/D/C/E、计数 5；便签及其他设置保留，遗留悬浮球会话不让主窗消失。

### BOOT-003 启动尺寸及位置 [P1 U/N]

- 前置：工作区起点 X/Y、宽 W、高 H 足以容纳主窗；saved size 分别为空、600×650、小于最小、超过最大。
- 步骤：逐一启动，测量窗口外框；记录允许尺寸夹取结果 w/h。
- 预期：尺寸依次默认、已存、夹到最小、夹到最大；位置为工作区右侧留约 40px、竖直居中，再限制到工作区。不是直接复用上次屏幕外 x/y；各平台坐标单位按 FEATURES §2。

### BOOT-004 设置损坏 [P0 I/U]

- 前置：有效 N1，设置值分别为非法 JSON、null、数字、缺字段对象、非法 language/dockEdge/window。
- 步骤：每个变体单独启动。
- 预期：主窗可操作、N1 完整；无效项采用 §14.1 默认，合法项保留；不因设置损坏删库或无限加载。

### BOOT-005 全部读取失败及重试 [P0 I/U/N]

- 前置：已有 N1，注入数据库无法打开；另做设置和便签整体读取失败变体。
- 步骤：启动，观察 1.7 秒加载失败提示；解除故障后重启。
- 预期：失败时也出现可操作的完整主窗、空列表和默认设置；不覆盖原数据库；解除故障后的重启恢复 N1，不能把临时空列表持久化成清空。

### BOOT-006 开机启动入口 [P1 N]

- 前置：隔离账户/环境已允许开机启动，保存 N1 和非默认窗口尺寸。
- 步骤：通过系统启动入口启动应用。
- 预期：与普通启动相同的完整主窗、语言、数据、尺寸和加载反馈；不直接停在悬浮球或隐藏状态。

### WIN-001 主窗尺寸边界 [P1 U/N]

- 前置：完整主窗，分别在各 DPI 和三系统执行。
- 步骤：拖各边/角尝试缩到 299×449、300×450，放到 1000×800、1001×801；按系统最大化快捷操作/双击标题区。
- 预期：尺寸始终受合法上下界和工作区约束；主窗无最大化按钮，不因标题双击变为不受约束的最大化窗口；内容无第二套标题栏。

### WIN-002 移动与合并保存 [P1 I/N]

- 前置：N1，能观察写入次数和重开窗口状态。
- 步骤：在短于 300ms 的连续间隔移动/缩放 20 次；停止后等待保存；随即关闭再托盘恢复，最后重启。
- 预期：移动中不为每个事件写一次；停止后保存最后尺寸/位置，恢复可见；重启尺寸仍为最终值，启动位置按 BOOT-003；不能保存过程中的中间尺寸。

### WIN-003 保存失败与退出前落盘 [P0 I/N]

- 前置：已有已保存尺寸，注入一次窗口设置写失败。
- 步骤：改变窗口；等待提示；解除故障并重试；在最后一次变化不足 300ms 时执行正常退出。
- 预期：失败有保存失败反馈、便签不变；重试能保存；退出前最后状态落盘，不因合并定时器尚未触发丢掉最后尺寸。

### WIN-004 离屏与小工作区恢复 [P1 N]

- 前置：保存位置完全在已拔除副屏；另做超大窗口、任务栏占边、小于最大尺寸的工作区。
- 步骤：启动、隐藏恢复、打开编辑窗；运行中移除副屏后再次恢复。
- 预期：各窗口可见、按钮可达；位置夹入现有工作区，不能全在屏幕外，尺寸不越过有效工作区上限；便签与主窗正常尺寸不被悬浮球尺寸覆盖。

### WIN-005 标题栏数量和几何 [P1 U/N]

- 前置：主窗与编辑窗同时打开。
- 步骤：截图并读取外框/内容尺寸；分别检查置顶、最小化和关闭按钮数量。
- 预期：各一套自绘标题和三个按钮，系统标题栏/按钮为零；外框=内容区；主窗标题高 24px/Q 22px，编辑标题只文字；15.12px/600 字体和 18px 按钮胶囊符合 §3.3。

### WIN-006 标题拖动和控件隔离 [P1 U/N]

- 前置：主窗与编辑窗均可见，非置顶。
- 步骤：拖标题文字，再逐一点击三个窗口按钮；同时拖过按钮边界后松开。
- 预期：仅标题拖动移动对应窗口；按钮不发起窗口拖动；最小化只影响当前窗口，置顶走全局设置，主窗关闭只隐藏、编辑关闭只丢弃当前会话。

### WIN-007 关闭及进程驻留 [P0 N]

- 前置：N1 已落盘；分别显示完整主窗、主窗最小化、仅悬浮球。

### EDIT-002 关闭重开与锚点刷新 [P1 U/N]

- 前置：新建窗打开后取消，随后移动主窗到其他位置或副屏。
- 步骤：再次新建和编辑已有便签，各做两轮。
- 预期：每次新窗口按当前主窗位置/工作区计算；不能缓存启动时的零坐标或使用编辑窗自身作为锚点；不会多出窗口或焦点落在已关闭窗口。

### EDIT-003 尺寸边界与重排 [P1 U/N]

- 前置：独立编辑窗，分别中英文、MANY。
- 步骤：缩到 420×520，尝试再小；放至 1000×800，尝试再大；滚动附件。
- 预期：遵守最小/最大与工作区限制；正文、附件可达，底部保存/取消始终可用；不挤压主窗或产生第二套标题栏。

### EDIT-004 唯一实例与会话替换 [P1 U/N]

- 前置：编辑 A 尚未保存，已改正文并添加附件，预览/媒体输入有内容。
- 步骤：从主窗编辑 B，再点击新建。
- 预期：始终最多一个编辑窗；B 会话只含 B 原值，新建会话为空默认值；A 未提交修改丢弃，旧媒体输入、预览序号和附件不串入新会话；不弹普通未保存确认。

### EDIT-005 初始内容、焦点及标题同步 [P1 U/N]

- 前置：分别新建和编辑 A；打开时主窗为中文，随后切英文。
- 步骤：检查正文/颜色/置顶/附件；输入内容；切换语言及全局置顶。
- 预期：新建为空默认，编辑完整载入原值；正文获得输入焦点，标题准确区分新建/编辑并实时切语言；所有原生窗口的置顶状态同步，已输入内容不丢。

### EDIT-006 正文视觉与色板 [P2 U]

- 前置：520×640 编辑窗，遍历 12 色和长正文。
- 步骤：测正文、色板和页脚，聚焦/失焦并调整宽度。
- 预期：遵守 FEATURES §6.2 的奶白主体、平直白色 50% 正文区、140px 最小高、14px 字体/21.7px 行高；正文背景不跟颜色变；色块可换行，选中描边清楚；页脚为复选框、浅色取消、深色保存。

### EDIT-007 trim 与内部格式 [P1 I/U]

- 前置：新建，内容 TXT-TRIM。
- 步骤：保存，重新编辑、复制、导出。
- 预期：各观察点内容严格为 `first  line\n\n second line`（真实换行），内部双空格、空行及第二段前空格保留；不压缩为单行或截断。

### EDIT-008 空白保存与附件例外 [P1 I/U]

- 前置：TXT-WHITE 的每个变体；分别无附件/有 M1。
- 步骤：保存。
- 预期：无附件按取消处理、计数不增、无空便签；有附件可创建纯附件便签，正文保存为空串，M1 全部保留。

### EDIT-009 保存新便签全部字段 [P0 I/U]

- 前置：冻结 T0，新建正文、指定第 7 色、置顶、M1。
- 步骤：推进到 T0+1000 保存，重启并导出。
- 预期：唯一新 id、createdAt/updatedAt 为保存时刻、颜色 `#d0ebff`、pinned=true、附件全字段不变、textHeight=null；放置顶组顶部，编辑窗关闭，主窗刷新、成功提示一次。

### EDIT-010 保存已有便签 [P0 I/U]

- 前置：A 有手调高度，记录其 id/createdAt/顺序，冻结时钟。
- 步骤：修改正文、颜色及附件，推进时间保存，重开编辑并重启。
- 预期：id/createdAt/原 textHeight 保留（显示高度按新正文夹取），updatedAt 为新时间；未改置顶则手排保持，其他字段只有指定变化，不产生第二条 A。

### EDIT-011 保存失败、保持草稿与重试 [P0 I/U]

- 前置：已有 A，草稿改文本、颜色、置顶并替换附件；注入附件替换后写入失败。
- 步骤：保存；检查卡片、数据库和编辑输入；解除故障再次保存。
- 预期：失败时编辑窗及全部草稿仍在，主窗和数据库完整保留原 A；失败提示约 1.7 秒；重试仅一次提交最终草稿，不生成残缺附件或重复便签。

### EDIT-012 取消入口矩阵 [P0 I/U/N]

- 前置：分别新建/已有 A，修改正文/颜色/置顶/附件；预置对应恢复记录。
- 步骤：分别取消按钮、自绘关闭、系统关闭事件退出编辑，重启。
- 预期：无未保存确认；草稿不提交，A 完整原值，新建不落库；清除该会话恢复记录，重启不再弹出已取消草稿。

### EDIT-013 快速保存与关闭竞争 [P0 I/U]

- 前置：写入人为延迟，已有 A 的修改草稿。
- 步骤：连续点击保存、保存后立刻点击取消/关闭，各变体独立执行。
- 预期：最多一次有效提交；若已成功提交，主窗和库均为同一结果；若取消先结束会话，旧异步回调不能关掉下一次新开的编辑窗或覆盖新会话；无重复记录。

### EDIT-014 悬浮球中发起编辑 [P1 U/N]

- 前置：A 存在，主窗已切球；通过可用编辑请求入口触发编辑 A/新建。
- 步骤：发送真实用户可触达的编辑动作；若平台没有该直接入口，则先托盘恢复再编辑并注明入口。
- 预期：完整主窗先恢复，独立编辑可见且激活；球与主窗状态不冲突，主窗不变成 30×30，A 内容准确。

## 9. 添加附件、拖放、粘贴与草稿隔离

依据：FEATURES §6.3、§6.4、§14。每条添加用例保存后必须重开编辑核对 value/source/kind/name/顺序，不能只看缩略图加载成功。

### ATTACH-001 多选图片及嵌入字节 [P1 I/U/N]

- 前置：空新建窗，IMG-A/B/C 的受支持选择器格式；原文件可移动。
- 步骤：一次多选图片；保存；移动原文件；重启并预览/导出。
- 预期：按选择结果加入对应数量附件，source=data、kind=image、名称保留，解码字节与夹具一致；移动源文件后仍可显示。不能把选择器的临时路径当持久值。

### ATTACH-002 选择器取消、重复选择和读取失败 [P1 U/N]

- 前置：草稿有正文和 M1。
- 步骤：取消图片选择器；连续两次选择同一图片；另注入文件读取失败。
- 预期：取消不改变草稿、不显示成功；重复选择都可添加且 id 不同；失败有读取错误，已有正文和附件不丢，不留下无法解码的伪成功附件，解除故障能重试。

### ATTACH-003 手动输入分类参数 [P1 L/U]

- 前置：空草稿，按下表每行独立执行，分别用 Enter 和添加按钮。
- 步骤：输入后提交；检查附件；保存再读取。
- 预期：按表分类；首尾空白去掉、内部字符保留，成功清空输入，空值不加入。

| 变体                | 输入                                     | source | kind   |
| ------------------- | ---------------------------------------- | ------ | ------ |
| http 图片           | URL-IMG                                  | url    | image  |
| https 图片          | 同路径改为可控 https 服务                | url    | image  |
| 带查询/片段大写扩展 | `/photo.PNG?x=1#preview` 的完整 http URL | url    | image  |
| 路径图片            | 含中文/空格的 IMG-A 绝对路径             | path   | image  |
| data 图片           | 完整 DATA-IMG                            | data   | image  |
| data 普通文件       | 完整 DATA-FILE                           | data   | file   |
| 普通网络文件        | URL-FILE                                 | url    | file   |
| 普通本地文件        | PATH-FILE                                | path   | file   |
| 无扩展路径          | 隔离目录下一个无扩展文件路径             | path   | file   |
| 空输入              | 空串/仅空白                              | 不添加 | 不添加 |

### ATTACH-004 扩展名矩阵 [P1 L/U]

- 前置：每个 `avif/bmp/gif/jpeg/jpg/png/svg/webp` 扩展名，分别大写/小写、URL/本地路径、带/不带 URL 查询和片段。
- 步骤：手动加入；另加入 `.pdf`、`.txt`、`.png.txt`。
- 预期：八种图片扩展均识别 image；最后三项为 file；依据真实末尾扩展名，不能被目录名或 query 中的 `.png` 误导。

### ATTACH-005 本地系统文件拖入 [P1 I/U/N]

- 前置：打开编辑窗，IMG-A 与 PATH-FILE 原文件在隔离目录。
- 步骤：从系统文件管理器一次拖入两个文件，保存、重启。
- 预期：原绝对路径保留，分别 image/path、file/path；名称准确，顺序对应此次拖入；不生成仅当前进程有效的对象 URL，拖入不触发窗口移动或正文替换。

### ATTACH-006 网页拖图片 URL 的优先级 [P1 I/U/N]

- 前置：一次拖放携带 uri-list、纯文本、HTML img src 和文件对象；其中指向同一 URL 的表示有重复。
- 步骤：从可控页面拖图片到编辑；保存。
- 预期：优先采用图片 URL，同次相同 URL 只加一项；有不同图片 URL 则保留对应不同项；不会为同一张图片再额外保存纯文本或文件对象数据。

### ATTACH-007 普通网页 URL 与文件对象兜底 [P1 I/U]

- 前置：分别只有普通 URL、只有浏览器文件对象、uri-list 含注释/空行的拖入数据。
- 步骤：逐一拖入。
- 预期：无图片 URL 时采用普通 URL；无 URL 时读取文件字节为 data；注释/空行不成为附件；原正文和现有附件不被清空。

### ATTACH-008 剪贴板截图及普通文本 [P1 U/N]

- 前置：正文焦点，剪贴板分别为 PNG 截图、普通多行文本、无图片内容。
- 步骤：用系统粘贴快捷键。
- 预期：截图加入 image/data，PNG 字节可往返；纯文本正常进入正文，不被图片处理器拦截；无图片不生成空附件，原内容保持。

### ATTACH-009 同名附件按标识删除 [P1 I/U]

- 前置：M1，两张图名称相同、两文件也可设为同名。
- 步骤：删除指定 id 的图及一个文件；检查另一个同名项；保存、重启。
- 预期：只删目标 id；其他同名项及顺序、字节保持；缩略图删除按钮不同时打开预览。

### ATTACH-010 草稿删除后取消 [P0 I/U]

- 前置：已有 A+M1。
- 步骤：删除全部草稿附件、再添加新图；取消；重新编辑 A 并重启。
- 预期：正式 A 仍为原 M1，附件表不提前删除或增加；无游离的新草稿附件写入数据库。

### ATTACH-011 草稿删除后保存及失败 [P0 I/U]

- 前置：已有 A+M1，移除 m2、增加新图；成功与中途写失败各独立执行。
- 步骤：保存、重开库、重启。
- 预期：成功时仅保留最终草稿附件；失败时原 M1 完整，草稿仍含用户修改可重试；禁止“旧附件先删了，新正文没保存”的半状态。

### ATTACH-012 多附件滚动与页脚可达 [P1 U]

- 前置：最小编辑窗、30 图+30 文件、长文件名，分别中英文。
- 步骤：滚动附件，删除末项，点保存或取消。
- 预期：附件区域独立滚动，名称截断仍能识别/查看完整值；底部按钮和置顶复选框不被挤出窗口；滚轮不意外修改图片预览缩放。

### ATTACH-013 图片失败与坏路径 [P1 I/U]

- 前置：URL 图 404、慢加载、坏字节、本地图片已移走，各独立夹具。
- 步骤：打开卡片/编辑/预览，期间编辑另一条、复制及删除失败附件。
- 预期：窗口持续可操作；失败不删除便签或改写附件值，其他图可显示，用户仍能移除/重试；关闭预览不一直显示阻塞加载罩。

### ATTACH-014 拖入高亮和取消 [P1 U/N]

- 前置：编辑有未保存正文。
- 步骤：文件拖入可接受区、移出、系统取消拖放，再重新拖入并放下。
- 预期：高亮按进入/离开/放下/取消恢复；未真正放下不添加；完成一次拖放仅增加一次，后续操作正常，不残留永久边框或捕获状态。

## 10. 图片预览

依据：FEATURES §7、§13；以下用例在主面板缩略图和编辑窗缩略图两个入口各执行一次。

### PREVIEW-001 打开、序号与初始态 [P1 U]

- 前置：3 张可辨识图片，点击第二张；正文有未保存改动。
- 步骤：打开预览并查看。
- 预期：深色遮罩覆盖当前窗口内容，图片 2/3、100%、居中、保持比例；预览取得键盘，编辑草稿不改变，主窗下层不复制。

### PREVIEW-002 关闭入口及点击隔离 [P1 U]

- 前置：已打开预览。
- 步骤：分别 Esc、关闭按钮、遮罩空白关闭；另点击图片、工具条和切图按钮。
- 预期：前三者只关闭一次，恢复原上下文；后三者不因遮罩监听误关预览；关闭按压不穿透为卡片复制/编辑保存。

### PREVIEW-003 首尾循环与单图 [P1 U]

- 前置：多图从首张/末张打开，另做单图。
- 步骤：上一张/下一张按钮、`[`/`]`、PageUp/PageDown 逐一执行；单图重复相同动作。
- 预期：多图首上一张到末、末下一张到首，序号准确；单图不显示切图按钮且键盘不产生错误索引或关闭预览。

### PREVIEW-004 切图复位 [P1 U]

- 前置：当前图片 200% 并平移，另做 50% 状态。
- 步骤：通过每个切图入口换图，再返回。
- 预期：每次切图均回到 100%、偏移 0，不能把上一图的缩放或移动继承给新图；相同名称图片仍按各自 id/顺序切换。

### PREVIEW-005 缩放按钮和边界 [P1 U]

- 前置：100%，可计数每次操作。
- 步骤：缩小两次到 50%，再缩小；放大到 600%，再放大；重复上下边界操作。
- 预期：每次 25%，不小于 50% 或大于 600%，百分比与实际图像变换一致；不累积浮点漂移或允许不可恢复的 0 大小。

### PREVIEW-006 键盘与滚轮等价 [P1 U/N]

- 前置：100%，输入焦点原先在正文。
- 步骤：分别按 `+`、`=`、`-`，滚轮向上/向下一个调整事件，及连续滚轮。
- 预期：分别 +25/+25/-25/+25/-25%，连续事件仍受边界限制；键盘不会往正文添加这些字符，滚轮不同时滚动下层附件。

### PREVIEW-007 重置入口 [P1 U]

- 前置：200% 且 x/y 非零。
- 步骤：分别按 0、重置按钮、双击图片。
- 预期：各入口归 100%、x=0、y=0，图片居中；双击不关闭预览或连续触发两次下层点击。

### PREVIEW-008 方向键的状态切换 [P1 U]

- 前置：3 图；先 50%、100%，再 125%。
- 步骤：每个缩放下按左/右/上/下。
- 预期：≤100% 左右切图，上下不平移；>100% 四键只平移、序号不变，每次 36px；左/上分别令图像 x/y 增大，右/下减小，达到边界后停止。

### PREVIEW-009 鼠标平移与取消 [P1 U/N]

- 前置：200%，另做 100%；鼠标左键/右键分别验证。
- 步骤：按住图像拖出原图范围、停住、反向、在窗口外松开；系统取消指针；再次移动。
- 预期：仅 >100% 左键平移，停指针停止、反向无跳动；离开图像仍跟随同次拖动，松开/取消立即停止；右键和 ≤100% 不平移，不误切图或触发恢复。

### PREVIEW-010 平移公式及缩小夹取 [P1 L/U]

- 前置：显示图片 W=800/H=500，舞台 S=600/T=400，z=2；相应布局固定。
- 步骤：拖超过四边；按方向键越界；缩回 100%。
- 预期：maxX=500、maxY=300，允许 x 为 ±580、y 为 ±380；超过立即夹取；≤100% 偏移归零。另用小图令 maxX/maxY=0，边界为 ±80 验证。

### PREVIEW-011 舞台尺寸与窗口变化 [P2 U/N]

- 前置：横图、竖图、透明图各一张，最小/最大主窗和编辑窗。
- 步骤：打开预览、调整窗口宽高、切图。
- 预期：舞台 54/44/42px 内边距，图片最大宽 min(1120,窗口宽-88)、高窗口高-108，按比例容纳、8px 圆角；28px 工具按钮位于顶/右 12px，关闭入口可见，图像不被错误拉伸。

### PREVIEW-012 键盘焦点与恢复 [P1 U]

- 前置：正文光标在中部，存在未保存内容。
- 步骤：打开预览、Tab 操作工具、按缩放/切图键、Esc 关闭，再继续输入。
- 预期：预览期间键盘归预览及其控件，不修改草稿；关闭后能返回编辑操作，原内容和选择上下文不被清空；Esc 不连带取消整个编辑会话。

### PREVIEW-013 加载失败与快速切换 [P1 U]

- 前置：慢图、404 图、正常图混合。
- 步骤：慢图加载未结束时快速切到正常图，再关闭预览；让旧请求结束后重开另一图。
- 预期：旧回调不覆盖当前图片/序号，不让已关闭预览复活；失败仍可切换/关闭，正常图可用，附件值不因失败被删除。

## 15. 未完成草稿与更新后恢复

依据：FEATURES §6.5、§14.2。普通编辑取消与更新恢复是不同生命周期，不能把所有输入自动保存为正式便签。

### DRAFT-001 脏状态矩阵 [P1 L/I]

- 前置：已有 A 的精确副本或新建默认草稿，冻结 T0。
- 步骤：分别只改正文、只改颜色、只改置顶、添加/删除/改变/重排附件；另做未修改和修改后完整改回原值。
- 预期：任一有差异为脏；未修改/改回完全原值为不脏；新建空白默认不脏，颜色或置顶单独改变也为脏，不能只比较正文。

### DRAFT-002 记录内容和副本隔离 [P0 L/I]

- 前置：可见脏编辑窗，A+M1，准备更新。
- 步骤：生成并保存恢复记录；继续改变当前草稿的附件名称、值和顺序；重读记录。
- 预期：记录含 draft/content/color/pinned/完整附件、noteId=A、savedAt=T0；保存时是独立副本，后续内存修改不改变已经生成的记录。

### DRAFT-003 不需要保存的会话 [P1 L/I]

- 前置：隐藏编辑、可见未修改、新建默认空白各变体；另有遗留恢复记录。
- 步骤：执行安装前草稿准备。
- 预期：不制造新的恢复记录；按有效会话清理规则处理旧记录，不能把隐藏/未修改窗口恢复成新便签；已有正式便签保持。

### DRAFT-004 已有便签恢复 [P0 I/U/N]

- 前置：A 在库，恢复记录指向 A 且含与 A 不同的草稿和 M1。
- 步骤：结束进程后启动；检查主窗和编辑；点击取消。
- 预期：完整主窗先出现，A 卡片仍为正式原值；自动打开编辑 A，内容为恢复草稿；取消后 A 不变、恢复记录清除，再重启不重复打开。

### DRAFT-005 新建及原便签不存在 [P0 I/U/N]

- 前置：noteId=null；另一组指向已不存在 id，draft 含正文和附件。
- 步骤：启动，保存恢复编辑，重启。
- 预期：两组都作为新建会话打开，保存产生唯一新纪录、旧不存在 id 不导致崩溃；保存后恢复记录清除，不重复创建第二份。

### DRAFT-006 严格字段校验 [P1 L/I]

- 前置：有效恢复记录副本，每次把 noteId 改成非法类型、savedAt 改成非有限值、draft 改为非对象、content/color 改非字符串、pinned 改为字符串、attachments 改非数组。
- 步骤：逐项解析并启动。
- 预期：整记录判无效，不打开伪造草稿，不把字符串 true 当布尔恢复；主窗仍正常显示已有便签，不能沿用宽松导入转换规则。

### DRAFT-007 任一附件非法则整体拒绝 [P1 L/I]

- 前置：有效 M1 中仅一项 id/value/name 类型非法、kind/source 未知、createdAt 非有限，各独立变体。
- 步骤：验证并尝试恢复。
- 预期：整条恢复记录无效，而不是静默过滤坏项后恢复一份缺附件的草稿；合法原记录可完整恢复，同名项保留。

### DRAFT-008 非法恢复 JSON 不阻止启动 [P0 I/U]

- 前置：N1，恢复值分别为截断 JSON、空串、null、无关对象。
- 步骤：启动并操作主面板。
- 预期：没有恢复窗，N1 完整可用，无无限加载；恢复异常不能触发清空便签或覆盖设置。

### DRAFT-009 保存/清除恢复记录失败 [P0 I/U]

- 前置：脏草稿；分别写恢复失败、用户取消时清除失败。
- 步骤：准备更新或取消编辑，检查错误、数据库和之后启动结果。
- 预期：保存恢复失败不能继续安装；清除失败不虚报已清除，原正式便签不变；记录实际后续恢复行为，不能用内存标志冒充磁盘已清理。

### DRAFT-010 普通关闭与更新退出区分 [P0 I/U/N]

- 前置：相同脏草稿，分别普通取消、系统关闭编辑、安装更新前准备后退出。
- 步骤：各场景独立结束后重启。
- 预期：前两种不恢复已丢弃会话；更新准备的有效草稿自动恢复。不能为了更新恢复而改变普通取消不保存的行为。

## 17. 悬浮球、真实坐标、四边吸附与多显示器

依据：FEATURES §12。此节的屏幕坐标必须来自真实窗口外框和真实鼠标位置；仅注入固定窗口内坐标的自动拖动不能证明没有反馈抖动。

### DOCK-001 两个切换入口和窗口外观 [P1 U/N]

- 预期：球固定 30×30、透明背景/无原生框/无标题按钮，内部黄底深色 Q，在有效工作区目标坐标约 180ms 淡入并位于当前窗口层级前方；完成首次显示后主窗才隐藏且保留尺寸和列表状态，恢复原实例并激活，不新建空列表。不能出现切换后找不到球、再打开托盘菜单才出现的状态；Windows 首显专项见 DOCK-022–025。

### DOCK-002 点击/拖动的 4px 边界 [P1 U/N]

- 前置：球处工作区中部；固定设计单位，每个参数重新收球。
- 步骤：分别原地点击、位移 3.9px、恰 4px、4.1px 后松开；另用斜向 (3,3) 距离约 4.24px。
- 预期：≤4px 按点击恢复，>4px 只移动不恢复；以二维距离判定，不能 x/y 分别都未过 4 就把斜拖当点击。对应实现若边界不符应记录失败，不改成“差不多”。

### DOCK-003 同 DPI 位移一对一 [P1 N]

- 前置：球远离四边，按下点分别中心、距左 6px/顶 20px；各 DPI 100/125/150/200%。
- 步骤：真实鼠标向右 120 个物理像素、向上 60 个物理像素，途中暂停三次、反向回起点；连续采样鼠标及窗口外框。
- 预期：同一物理坐标单位下球分别 +120/-60，允许取整误差；按下点相对球保持。逻辑位移应为物理位移/该屏比例；窗口本身移动不能改变下一次增量原点，持续同向不反跳、停鼠标球停止，回起点无累积漂移。

### DOCK-004 快慢、窗口外释放和取消 [P1 N]

- 前置：球在中部，保持不触工作区边界。
- 步骤：快速 300px 拖、慢速 1px 连续拖、拖出原 30px 窗口后松开、系统取消捕获；之后只移动鼠标。
- 预期：均完整结束拖动，最终球不继续跟随、不抖动、不恢复主窗；下一次点击和拖动仍可用，不留 dragging 状态。

### DOCK-005 工作区夹取 [P1 N]

- 步骤：分别拖向四边以外，并在未吸附时观察完整球位置。
- 预期：自由拖动完整球原点限制在 x∈[X,X+W-30]、y∈[Y,Y+H-30]；以当前屏工作区而非全屏计算，不挡在任务栏后；松开后吸附与半隐藏另按以下用例。

### DOCK-006 四边吸附边界矩阵 [P1 L/N]

### DOCK-007 最近边与同距角落 [P1 L/N]

- 步骤：释放并检查吸附边缘和沿边位置。
- 预期：选最近边；等距按 left/right/top/bottom 优先序，不能每帧交替选择两边造成对角抖动；沿边位置夹入工作区。

### DOCK-008 半隐藏的尺寸、方向和裁剪 [P1 U/N]

- 前置：球刚吸附四边之一，分别所有四边执行。
- 步骤：记录 130ms 动画的路径与终点；检查相邻显示器和球透明区。
- 预期：约 130ms 向对应屏外移动半径 15px，只露半圆；不缩小内容为 15×30 或改变主窗尺寸；Windows 原生裁剪使隐藏部分不泄露到相邻屏，不产生矩形黄块或原生阴影框。

### DOCK-009 hover 展开与再次隐藏 [P1 U/N]

- 前置：四边半隐藏球。
- 步骤：鼠标进入可见半圆，停住，再移出完整球，重复五次。
- 预期：进入完整滑出到原锚点、离开半隐藏；终点固定、无连续来回振荡；保持鼠标不动时不因窗口运动重启同一方向动画，点击区域与可见半圆一致。

### DOCK-010 动画中发起拖动 [P1 N]

- 前置：半隐藏滑出/收回动画处于 0/中段/接近结束三种时刻。
- 步骤：从可见区域按下并拖超过 4px；拖动中触发进入/离开；工作区中部释放。
- 预期：拖动取得控制后取消旧动画并清除剪裁、可拖区域完整；hover 不抢回控制，不同时计算隐藏和鼠标移动；释放中部不残留半隐藏或边缘标记。

### DOCK-011 菜单定位与不依赖主窗 [P1 N]

- 前置：球在屏幕中部，隐藏主窗在相距很远处；四边、负坐标副屏和各 DPI 另做变体。
- 步骤：真实右击球内指定点，测菜单位置；改变主窗位置后再次右击。
- 预期：菜单紧邻右击的真实屏幕点，只有无法放入工作区时向内避让；不出现在隐藏主窗附近、不乘错 DPI、不因主窗移动改变相同球点的菜单锚点。右击不恢复主窗或开始拖动。

### DOCK-012 菜单期间冻结半隐藏 [P1 N]

- 前置：贴边完整/半隐藏球，打开菜单。
- 步骤：把指针从球移入菜单并停留超过 500ms；取消或选择语言/置顶后关闭菜单。
- 预期：菜单期间球不自动收回或振荡，菜单命中不漂移；关闭后按实际 hover/吸附状态恢复，菜单选择不误成球单击。

### DOCK-013 拖动后的误点抑制 [P1 U/N]

- 前置：自由球。
- 步骤：拖动释放，再记录系统附带 click；抑制结束后主动单击。取消拖动也执行。
- 预期：释放和取消的附带点击不恢复主窗；后续独立单击可以恢复，不永久吞点击，不延迟补发旧恢复动作。

### DOCK-014 恢复主窗时保存原几何 [P0 I/N]

- 前置：主窗保存 600×650，自由球/贴边球各一组。
- 步骤：球点击恢复、托盘恢复、球菜单恢复分别测试；等待超过窗口保存延迟，重开设置并重启。
- 预期：主窗仍 600×650、可见并激活，最后主窗几何不被 30×30 或半隐藏坐标污染；重启显示完整主窗。

### DOCK-015 五分钟位置缓存精确边界 [P1 L/N]

- 前置：从左/右/上/下贴边球恢复主窗，记录时间和沿边位置；可控时钟。
- 步骤：分别在 299999ms、300000ms、300001ms 再收球，各用独立会话。
- 预期：前两组恢复旧边和沿边位置，最后一组过期按当前主窗新位置计算；不因读取缓存更新其有效期，缓存是会话位置而非正式便签数据。

### DOCK-016 回到缓存位置的 500ms 延迟 [P1 L/U/N]

- 前置：有效贴边缓存，主窗切回球，鼠标不在球上。
- 步骤：以球首次原生可见为计时起点，检查 499ms、500ms、再过 130ms；另在延迟中 hover 或开始拖动。
- 预期：499ms 完整可见，500ms 后进入半隐藏，动画结束露半圆；约 180ms 淡入计入这段等待，不能淡入结束后再额外等 500ms。hover/拖动后的最终行为服从最新操作，旧计时器不在拖动中把球拉回边缘。

### DOCK-017 同比例跨屏和负坐标 [P1 N]

- 前置：双屏比例相同，副屏在左/上，各有任务栏工作区。
- 步骤：真实拖球跨屏到另一屏中部及四边；释放、恢复、再次收球。
- 预期：以球当前屏工作区计算夹取/28px 吸附，负坐标合法；不锁死在主屏、不突然跳到 (0,0)，位置缓存属于正确屏。

### DOCK-018 混合 DPI 跨屏 [P1 N]

- 前置：主屏 150%+副屏 100%，再做 200%+125%，记录各屏物理与逻辑边界。
- 步骤：由非中心点按下，缓慢跨屏、回拖、停住，再快速跨屏；对新屏做吸附和右击菜单。
- 预期：每屏上的物理移动匹配鼠标，视觉球尺寸按系统缩放正确；不按一个统一比例换算所有全局坐标，不产生倍速、半速或反馈抖动；跨屏后菜单和吸附仍按目标屏。

### DOCK-019 缓存屏移除及工作区缩小 [P1 N]

- 前置：球贴副屏边后恢复主窗并保存缓存。
- 步骤：拔掉副屏或改变任务栏占用，再于五分钟内收球。
- 预期：球回到当前可用工作区且完整位置可达；保留可适用的原边缘语义、沿边位置夹取，不使用已失效屏幕坐标，也不影响便签数据。

### DOCK-020 快速往返和最后操作优先 [P0 U/N]

- 前置：N1+非默认主窗尺寸，编辑窗可存在。
- 步骤：连续十次主窗/球切换、托盘恢复与球单击交替，覆盖 180ms 淡入/130ms 贴边/500ms 等待中打断。
- 预期：最终可见状态服从最后一次有效操作；不会全部窗口不可见、出现多个球或主窗、30px 尺寸误持久化、旧动画移动新实例；N1 和草稿不丢。

### DOCK-021 能力缺失时降级 [P1 I/N]

- 前置：平台不支持定位、获取工作区或原生裁剪，分别模拟能力不可用/调用失败。
- 步骤：启动、收球、移动、吸附、恢复、退出。
- 预期：应用仍能保存和找回数据、恢复可见主窗；缺失效果有安全降级，不能因窗口定位失败启动崩溃或把不可见窗口误记为成功；报告未提供的能力和实际降级行为。

### DOCK-022 Windows 首次切球无需托盘干预 [P0 N]

- 前置：Windows 隔离数据 N1，主窗 600×650 且位于工作区内、处于激活状态，无有效贴边缓存；指针在预计球位置之外。主窗 Q 与托盘菜单两个入口、冷启动后的第一次切换与同会话恢复后的再次切换分别执行；开发宿主和实际便携程序分别执行，记录运行目录和提交。按第 2.2 节记录 DPI/屏幕/工作区及普通/置顶设置。
- 步骤：从切换前开始录制真实桌面并只读采集窗口外框、原生可见状态和层级；触发切球后保持指针静止，观察首次原生呈现、约 180ms 淡入结束和主窗隐藏。此阶段不再点击托盘、不打开任何菜单、不主动聚焦球、不移动/激活其他窗口，也不允许测试驱动或截图工具额外 show/focus。确认结果后才允许点击球恢复；失败时先保留未经托盘干预的画面和状态，再按 DOCK-023 收集诊断。
- 预期：球从有效工作区内的目标坐标打开，淡入结束时真实桌面可直接看见 30×30 的 Q，位于当前窗口层级前方；完成呈现后主窗才隐藏，交接不留下全部窗口不可见的状态。无需第二次输入、托盘菜单或外部重绘才出现；只报告 visible=true、尺寸正确或单窗口离屏截图不算此项通过。球单击后恢复原主窗、尺寸、N1 和滚动位置；每个环境变体单独记录结果，工具拿不到桌面证据时注明缺口。

### DOCK-023 Windows 托盘菜单不补救或破坏首显 [P1 N]

- 前置：按 DOCK-022 完成首显并保留操作前的桌面证据；球处工作区中部且无待执行贴边动画，主窗隐藏。普通/置顶两组，中文/英文分别执行；必须操作系统通知区域的真实应用图标，不能用球菜单或模拟菜单代替。
- 步骤：记录球位置和可见性，再右击托盘打开菜单；分别用 Esc、点击菜单外空白处取消，独立执行并记录菜单打开及关闭后的状态。若 DOCK-022 失败，先保存首显失败证据，再执行同样的托盘操作比较前后；该次记录用于诊断，不能把补出现的球计作首显通过。
- 预期：正常路径中打开托盘菜单前球已经可见；菜单打开和取消后球仍在原坐标、保持原置顶设置，主窗仍隐藏，无闪失、跳到 (0,0)、重复球或误恢复。托盘菜单可以按规则抢占输入，但不能承担首次显示球的必要步骤；出现“打开菜单后球才出现”即首显回归失败。取消菜单不触发任何菜单动作，后续球点击仍能恢复主窗。

### DOCK-024 Windows 普通/置顶各三次往返的显示交接 [P1 N]

- 前置：N1 加 30 条普通短便签（i=1…30，id 为 FLOAT-i、正文为“浮球回归 i”、sortOrder=2+i，其他字段同第 3.2 节），主窗 600×650；列表滚动到可滚动距离的一半并记录偏移，无有效贴边缓存。分别持久化 alwaysOnTop=false/true 并核对系统状态。放置普通参考窗口于主窗之后，覆盖球的预计目标区域，用于观察主窗隐藏后的实际层级；避免系统模态窗口和其他永久置顶窗口干扰。两个切球入口、开发宿主/便携包分别执行。
- 步骤：每种设置连续三次切球并单击球恢复，每次都先按 DOCK-022 无额外输入地观察球，再检查外框、实际桌面层级及主窗状态；第三次恢复后重开设置并检查持久化值。
- 预期：每次球都在当前层级前方可见，普通窗口下也不能被原本在主窗后的参考窗口遮住；置顶开启时球保持置顶，关闭时仍属普通窗口，不能靠无条件永久置顶解决显示问题。三次往返不累积位移、不遗留旧球，恢复后主窗尺寸、全部便签、记录的列表偏移与置顶设置保持；不把 30×30 球尺寸写成主窗尺寸，也不需要打开托盘促成显示。

### DOCK-025 Windows 切球未完成时恢复与重新切换 [P0 I/U/N]

- 前置：N1、非默认主窗几何，隔离保存与窗口生命周期；准备可控延迟，分别停在主窗几何保存待完成、球首次原生呈现前、约 180ms 淡入中段。每个阶段独立复位；允许集成层控制完成顺序，但原生首显结论仍需实际 Windows 桌面证据。
- 步骤：每阶段触发切球后，通过有效的托盘恢复入口恢复主窗，再放行旧保存/呈现/动画的完成；另做恢复后立即再次切球、让新球先完成再释放旧回调的变体。继续推进所有旧计时器及约 500ms 贴边等待，检查最后一次有效操作之后的窗口和持久化状态；新球首显也遵守 DOCK-022，不能由驱动额外激活。
- 预期：最后操作为恢复时，主窗可见且激活、没有可见旧球；旧请求完成不能再次隐藏主窗、切回球模式或移动窗口。最后操作为切球时，只显示一个当前球并按正常呈现顺序隐藏主窗；已关闭实例的动画、裁剪、定位或隐藏回调不能作用于新实例，旧保存响应不能覆盖新几何。两条路径均保留 N1、草稿、主窗尺寸和原置顶设置，不把球尺寸持久化，不遗留无限等待；DOCK-016 的等待起点和 DOCK-020 的快速切换要求同时成立。

## 18. SQLite、历史库与迁移后的数据兼容

### 18.1 可独立生成的数据库夹具

兼容结构如下，列名是历史持久化契约，类型中的布尔用 0/1，时间用毫秒整数。不能只用内存对象测试声称“兼容旧库”。

```sql
CREATE TABLE notes (
  id TEXT PRIMARY KEY NOT NULL,
  content TEXT NOT NULL,
  color TEXT NOT NULL,
  pinned INTEGER NOT NULL DEFAULT 0,
  text_height INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE attachments (
  id TEXT PRIMARY KEY NOT NULL,
  note_id TEXT NOT NULL,
  source TEXT NOT NULL,
  value TEXT NOT NULL,
  name TEXT,
  created_at INTEGER NOT NULL,
  kind TEXT NOT NULL DEFAULT 'image',
  FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE CASCADE
);
CREATE TABLE settings (
  key TEXT PRIMARY KEY NOT NULL,
  value TEXT NOT NULL
);
```

settings 的 `app` 行保存完整设置 JSON；`pending-update-editor-draft` 行保存恢复 JSON。历史 v1 结构不含 attachments.kind 和 notes.sort_order；v2 增加 kind，原记录默认 image；v3 增加 sort_order，已有记录使用负 updated_at，并按 pinned/顺序/更新时间排序。生成历史夹具时分别去掉对应列；当前框架若另有迁移账本，测试适配器负责配套合法账本，不能改变产品数据字段或用新空库替代旧库。

标准数据库夹具写入 N1+M1 和 S1，检查 notes 与 attachments 的关联；另生成 WAL 模式且有未 checkpoint 的已提交便签，保持源连接打开直到迁移测试完成。故障测试在事务中点注入，不改用户权限或真实数据目录。

### DB-001 数据目录与建库时机 [P0 I/N]

- 前置：隔离用户目录与旧位置均不存在数据库。
- 步骤：启动并新建一条，正常退出；检查实际打开文件。
- 预期：Windows 用户目录 `.q-note/q-note.db`、macOS/Linux 对应主目录位置创建数据；不能误写到程序安装目录或当前工作目录；目录不存在可正常创建，不接触真实用户库。

### DB-002 先迁移旧库再开新库 [P0 I/N]

- 前置：Windows 旧 `%APPDATA%/com.win11.q-note/q-note.db` 有 N1+M1，新位置不存在。
- 步骤：首次启动，记录文件创建/打开顺序，读取新旧库。
- 预期：先复制完整旧数据再打开/创建新库；新库显示 N1+M1，旧库保留且可读；不得先创建空新库导致跳过迁移。

### DB-003 新位置存在绝不覆盖 [P0 I/N]

- 前置：旧库 N1；新库分别含另一条 X、合法空库两组。
- 步骤：启动、退出，再重启。
- 预期：两组均以新库为准，不被旧 N1 覆盖；空库存在也不能触发“恢复旧数据”；源旧库不删除。

### DB-004 活跃 WAL 已提交数据 [P0 I/N]

- 前置：旧库 WAL 模式，保留连接，新增一条已提交但未合并进主 db 文件的 WAL-NOTE；新位置不存在。
- 步骤：迁移并打开目标；核对 WAL-NOTE、N1、附件和设置；检查源库。
- 预期：目标包含全部已提交数据，不只是复制主 db 丢最后一批；源可继续读；不得仅靠文件存在就判迁移成功。

### DB-005 复制失败与重试 [P0 I/N]

- 前置：旧库完整、新库不存在，注入目标写/复制失败。
- 步骤：启动并检查反馈、源及不完整目标；解除故障再启动。
- 预期：源数据不损坏，失败不得被当成一个完成的新空库；再次启动有机会迁移成功；不会无限加载或静默清空旧库。

### DB-006 v1/v2/v3 结构升级 [P0 I]

- 前置：按 §18.1 分别生成三份有数据的历史库，记录全部原字段。
- 步骤：用被测实现打开，读取和编辑一条，再正常退出/重开。
- 预期：缺少 kind 时补默认 image，缺少 sort_order 时按 -updated_at 建立顺序；已存在的合法列不被重复添加/清零；原 id/时间/高度/附件/设置保留，无“表已存在/重复列”启动失败。

### DB-007 全字段读写与字段映射 [P0 I]

- 前置：列值刻意可区分，SQL 查询列顺序与驱动返回对象键顺序不同；有 null 名称、高度、同名附件。
- 步骤：读为产品数据，修改正文后保存，再直接 SQL 核对。
- 预期：content 不变成 color、pinned 不变成时间，sortOrder/textHeight 与各自列正确对应；空值语义保留，附件仍归正确 note_id；不能依赖对象键碰巧按 SELECT 顺序排列。

### DB-008 单条保存及附件事务 [P0 I]

- 前置：A+M1，待替换正文和附件；分别在写正文、删除旧附件后、插入第二个新附件时失败。
- 步骤：保存，重开数据库比较完整快照。
- 预期：每个失败点都保留完整旧 A+M1，不能有新正文旧附件或相反；成功变体一次提交所有新值，事务不泄露到后续操作。

### DB-009 删除和全删事务 [P0 I]

- 前置：N1+M1，分别在删除附件后/删除便签前/提交时失败。
- 步骤：单删与全删分别验证；重开连接。
- 预期：失败全回原快照，成功仅删除目标及关联附件，全删保留设置；没有孤立附件、部分删除或因连接仍未提交而误判通过。

### DB-010 重排和导入事务 [P0 I]

- 前置：N1+S1，目标跨分组重排和新 JSON 替换；在第二项写入及 commit 处分别失败。
- 步骤：执行，关闭连接重开并重启 UI。
- 预期：顺序/置顶与 notes/attachments/settings 分别作为完整事务；失败不留半顺序或半导入，下一次合法事务仍可成功。

### DB-011 更新或换栈打开原库 [P0 I/N]

- 前置：原版本生成的真实库，包含所有字段和恢复记录；先备份隔离副本。
- 步骤：新实现打开副本，读取、编辑、复制、导出、重排、重启；再由原版本打开同一副本。
- 预期：新旧双方均可读写合法数据，字段、标识和附件字节不丢；不要求用户改库或手工搬文件；新实现专属元数据不能破坏原数据结构。

### DB-012 锁定/只读与失败后恢复 [P0 I/U]

- 前置：已有数据；使用隔离库锁或可控存储错误，不更改用户真实目录权限。
- 步骤：读可成功但写失败时进行编辑/删除/排序/设置/导入；解除故障重试。
- 预期：各动作遵守原值保留和对应失败反馈，界面仍可使用；解除后队列/连接恢复，不因一次失败永久拒绝后续写入。

### CROSS-008 失败后完整用户旅程 [P0 I/U/N]

- 预期：每步失败保持原数据并可重试，重试后下一步不受残留 loading/dragging/事务影响；最终库、导出和 UI 内容一致，所有窗口可关闭与恢复；记录每一步证据，不用“旅程完成”掩盖中途失败。
