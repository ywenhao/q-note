## WIN-FLOAT-001：切成悬浮球后不可见，打开托盘菜单才出现

### 发生与确认

- 平台：Windows；发生在 NSH 版本的主面板/悬浮球切换。
- 用户观察：切换到悬浮球后找不到球；右击任务栏通知区域的应用图标、打开托盘菜单时，球又出现。
- 修复提交：[bcf0299](https://github.com/ywenhao/q-note/commit/bcf02999ada1391bebe3164dbf81ea85731cfeb7)，分支 nsh，日期 2026-11-11。
- 修复后用户明确反馈：“我手动测试 修好了”。这是该症状的人工确认。
- 本次人工反馈没有附 Windows 构建号、DPI、显示器布局或完整参数记录，不能据此宣布所有 DPI、多屏和打断场景通过。

### 已确认的应用层问题

旧的切换路径先修改球模式状态、隐藏主窗口，再通过 0ms 定时器查找球窗口、设置坐标并调用显示。球窗口创建、原生首次呈现和透明内容淡入有各自的完成时点；排入定时器不等于原生窗口已经完成显示。球还配置为显示时不自动激活，旧流程没有在交接完成时明确将其带到当前层级前方。

这种交接没有建立“用户已经能看见球，才能隐藏主面板”的条件。后续托盘菜单引起的窗口消息、绘制或前景变化可能掩盖问题，因此“先右击托盘再检查球”会漏掉原始缺陷。

以上是已核对的应用代码时序及修复范围；没有把某个 Windows 系统调用或 NSH 引擎内部缺陷确定为唯一原因。以后复现相同症状时，仍需检查实际创建、绘制、透明度、工作区和窗口层级。

### 本次修复采用的交接顺序

1. 保存主窗口几何；计算并限制球的目标坐标到当前有效工作区。
2. 创建球窗口时就给出目标位置，尺寸为 30×30；保留当前全局置顶设置。
3. 等原生窗口报告可见，再开始约 180ms 的淡入。
4. 只有淡入完成、仍处于球模式、且回调对应当前球实例时，完成球的定位、清除过期裁剪、带到当前层级前方，再隐藏主窗口。
5. 恢复主面板时撤销尚未完成的切换请求；窗口卸载时停止淡入。已取消请求或旧窗口回调不能再次隐藏主窗、显示旧球或移动新球。
6. 对有效贴边缓存，约 500ms 的等待从球首次可见时计时，淡入耗时不再额外加一遍；之后仍沿用半隐藏与 hover/拖动互斥规则。

### 以后 Windows 实现必须保留的约束

- 先建立目标窗口的实际呈现条件，再隐藏来源窗口；不能把状态变量已更新、窗口引用非空或 0ms 定时器已执行作为显示完成信号。
- 将“窗口存在”“系统可见”“内容完成淡入”“位于工作区内”“在当前层级前方”分开检查。完全透明、被其他窗口盖住、坐标在屏幕外都可能表现为“球丢了”。
- 原生 visible=true、30×30 尺寸和单窗口离屏截图都不能单独证明用户在桌面上已经看见球；需要实际桌面观察或录屏核对合成结果。
- 保留普通/置顶两种全局设置。带到当前层级前方不能变成无条件永久置顶，不能靠修改用户置顶设置掩盖显示问题。
- 主窗 Q 入口不操作托盘；托盘入口只允许完成触发切球的必要菜单动作。触发后，在首次显示检查完成前不再点击托盘、不打开任何上下文菜单、不主动激活球、不让截图工具先聚焦球，也不通过测试驱动调用额外 show/focus 帮助被测应用。
- 关闭、恢复或重新创建期间取消旧动画、定时器和待完成请求；异步完成时同时核对当前模式和窗口实例。
- 浏览器或无头模拟不能代替 Windows 托盘、透明原生窗口、前景层级和首次桌面呈现验证。
- 验证开发宿主与实际便携程序。重新打包后记录真实运行的目录和提交，避免仍在运行旧 EXE。
