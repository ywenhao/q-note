# Q Note Slint 迁移需求与实现节点

> 分支：`slint`  
> 基线：`gpui` 分支 `4ca0be5`  
> 原则：功能、交互、数据兼容优先；统一视觉令牌；按节点实现、验证并回写状态。
> 本文件是本次 Slint 迁移的历史实现记录；当前功能事实与后续迁移基线以 [`FEATURES.md`](./FEATURES.md) 为准。

## 1. 迁移目标

- 使用 Rust + Slint 重写桌面 UI，不引入 Vue、React、Tauri 或 WebView。
- 保留当前 GPUI 版的完整能力和交互，不把“框架暂不方便”当作删功能理由。
- 继续读写 `~/.q-note/q-note.db`，沿用当前 SQLite schema、JSON 导入导出格式和旧数据迁移规则。
- 保留主面板 `#ffd150`、编辑器 `#fff9df`、12 色卡片色板和紧凑桌面便签定位。
- 中英文界面同步；新增或调整的用户可见文本统一放在 `src/i18n.rs`。
- Windows、macOS、Linux 的平台行为保持现有降级策略；当前开发机先完成 Windows 验证。

## 2. 不变约束

### 2.1 数据

- 数据库路径：Windows 为 `C:\Users\<username>\.q-note\q-note.db`，macOS/Linux 为 `~/.q-note/q-note.db`。
- 首次运行且新路径不存在时，继续从旧 Tauri 路径 `%APPDATA%/com.win11.q-note/q-note.db` 复制数据库。
- 保留 `notes`、`attachments`、`settings` 表及现有迁移逻辑。
- 保留字段：内容、颜色、置顶、手动顺序、文本显示高度、附件 kind/source/value/name、创建/更新时间。
- 保留设置：语言、窗口置顶、开机启动、悬浮球/贴边状态、窗口尺寸和位置。
- JSON 导入仍为“整体替换”；选择文件被取消时不修改数据；不得在其他流程中删除用户数据。
- 更新或退出前继续落盘设置、未完成编辑草稿，并 checkpoint WAL。

## 4. Slint 结构规划

### 4.1 Rust 层

- `src/main.rs`：Slint 事件循环、应用启动和退出收口。
- `src/app_state.rs`：去除 GPUI 类型，保留领域状态、持久化操作和跨窗口刷新通知。
- `src/windowing.rs`：主窗/编辑窗/悬浮球生命周期、位置、置顶和平台原生能力。
- `src/tray.rs`：保留 `tray-icon`，通过 Slint 事件循环代理派发命令。
- `src/storage/`、`src/models.rs`、`src/note_ordering.rs`、`src/updater.rs`、`src/autostart.rs`：尽量原样复用，只移除 UI 框架耦合。
- `src/slint_bridge.rs`：Rust 模型与 Slint 属性/回调映射，集中处理刷新，避免业务逻辑散落在 UI 回调中。

### 4.2 Slint 层

- `ui/tokens.slint`：颜色、尺寸、圆角、文字层级和状态色。
- `ui/components.slint`：Q 标识、标题栏按钮、工具按钮、色板、toast、弹层基础组件。
- `ui/main-window.slint`：主面板、工具栏、便签列表、卡片操作、设置/确认/更新/图片预览。
- `ui/editor-window.slint`：编辑器、附件列表和图片预览。
- `ui/dock-window.slint`：30px 悬浮球视觉与指针回调。

Slint 只负责视图状态和事件上报；排序、保存、导入替换、更新校验、窗口状态等由 Rust 层负责。

## 6. 每个节点的执行规则

1. 开始节点前，把该节点标记为 `🟨 进行中`。
2. 只实现当前节点依赖的最小纵向切片，公共视觉必须复用令牌/组件。
3. 每完成一组交互，按第 3 节对应条目验证并勾选。
4. 每个节点至少执行 `cargo fmt --check` 和 `cargo check`；涉及持久化时额外验证旧数据库读写不改 schema。
5. 为临时验证创建的测试文件在节点完成后删除；复杂领域测试（例如排序/导入规范化）可以保留。
6. 节点完成后回写状态、已验证内容和已知平台差异，再进入下一节点。
